# botinok-temcshika

Лёгкий мост между **VK-беседой** и личками **Telegram**: пересылает `@all`-сообщения,
зеркалит голосования в виде инлайн-кнопок, дедуплицирует голоса по связке VK↔TG и
подводит итоги (в том числе обратно в VK-чат).

## Что умеет

1. **`@all` → личка TG.** Любое сообщение в беседе с тегом из `MENTION_TAGS`
   (`@all`, `@все`, `@online`) пересылается всем одобренным TG-пользователям
   (текст + фото).
2. **Зеркало голосований.** Когда в беседе появляется голосовашка, каждому
   одобренному пользователю приходит сообщение с инлайн-кнопками. Оно обновляется
   по таймеру (из VK) и при нажатиях кнопок.
3. **Дедупликация.** TG-пользователь привязывает свой VK-аккаунт (одноразовый код,
   отправленный в беседу). При подведении итогов нативные VK-голоса и TG-голоса
   объединяются по личности; **TG-голос привязанного пользователя перекрывает его
   VK-голос**. Для анонимных голосований дедуп невозможен — режим аддитивный
   (с пометкой).
4. **Завершение.** Голосование закрывается по `end_date` из VK **или** командой
   админа `/close` — что раньше. Кнопки снимаются, отдельным сообщением приходят
   итоги, итоги также постятся в VK-чат.
5. **Доступ.** Все заявки одобряет один захардкоженный админ (`TG_ADMIN_ID`).

## Стек

Go 1.22 · SQLite (`modernc.org/sqlite`, без CGO) · Docker.
VK — [SevereCloud/vksdk](https://github.com/SevereCloud/vksdk) (Bots Long Poll),
TG — [go-telegram-bot-api](https://github.com/go-telegram-bot-api/telegram-bot-api).

## Запуск

```bash
cp .env.example .env       # заполнить токены и TG_ADMIN_ID
docker compose up --build  # или docker-compose up --build
```

База лежит в `./data/bot.db` (том примонтирован).

### Что нужно от VK

- Сообщество, токен с правами `messages` + `manage`.
- В настройках сообщества включён **Long Poll API** (актуальная версия) и события
  `message_new`.
- Бот-сообщество добавлено в беседу; для чтения сообщений беседы у него должен быть
  доступ к перепискам (роль администратора беседы / «доступ к сообщениям»).
- `VK_PEER_ID` — `2000000000 + <id беседы>`; можно оставить `0`, чтобы реагировать
  на все беседы, которые видит бот.

## Пользовательский поток

1. Пользователь пишет боту в TG → улетает заявка админу (с кнопками «Одобрить /
   Заблокировать»).
2. Админ одобряет → пользователь начинает получать `@all` и голосования.
3. `/link` в TG → бот выдаёт код `vklink-xxxxxx` → пользователь отправляет его в
   VK-беседу → привязка происходит автоматически.

### Команды

Пользователь: `/start`, `/help`, `/status`, `/link`.
Админ: `/pending`, `/approve <tg_id>`, `/block <tg_id>`, `/polls`, `/close <poll_id>`.

## Схема БД

См. [internal/store/schema.sql](internal/store/schema.sql). Ключевые таблицы:
`tg_users` (доступ + привязка), `link_codes`, `polls` / `poll_options`,
`poll_tg_messages` (персональные TG-сообщения), `tg_votes` (локальные голоса),
`vk_voters` (снимок нативных голосующих для дедупа), `broadcasts` (идемпотентность
`@all`).

## Ограничения / заметки

- VK-вложения: пересылаются **только фото** (по URL, без перезалива байтов).
- Дедуп требует не-анонимного голосования и доступности `polls.getVoters`;
  иначе — аддитивный режим с пометкой.
- Голос из TG **не** уходит в нативную VK-голосовашку (по ТЗ — только локальный
  учёт и мердж).
- На каждое нажатие кнопки обновляются зеркала у всех пользователей — для больших
  бесед стоит добавить дебаунс.
